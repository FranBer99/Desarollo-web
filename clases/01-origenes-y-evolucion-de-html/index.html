Clase 01

Orígenes y evolución de HTML

Antes de escribir la primera etiqueta conviene entender qué problema resuelve HTML, de dónde viene y por qué el estándar que usamos hoy ya no tiene número de versión.

Objetivos
  • Definir qué es HTML y diferenciarlo de un lenguaje de programación.
  • Ubicar los hitos principales de la historia del estándar.
  • Reconocer la anatomía de un elemento y de una regla CSS.
  • Escribir y abrir un primer documento HTML válido.

¿Qué es HTML?

HTML son las siglas de HyperText Markup Language, es decir, lenguaje de marcado de hipertexto. No es un lenguaje de programación: no tiene variables, condiciones ni bucles. Es un lenguaje declarativo que describe la estructura y el significado del contenido mediante marcas o etiquetas.

Un documento HTML le dice al navegador qué es cada cosa: esto es un encabezado, esto es un párrafo, esto es una lista, esto es un enlace. A partir de esa información el navegador construye una representación en memoria —el DOM, que veremos en la próxima clase— y la dibuja en pantalla.

Las tres capas de una página web
Capa Lenguaje Se ocupa de…
Estructura y contenido HTML Qué información hay y qué significado tiene.
Presentación CSS Cómo se ve: tipografía, color, espacio, disposición.
Comportamiento JavaScript Cómo reacciona a las acciones del usuario.

Mantener las tres capas separadas es una de las ideas más importantes del desarrollo web: el mismo HTML puede verse de maneras muy distintas según el CSS, y puede funcionar sin JavaScript. Esa separación mejora el mantenimiento, la accesibilidad y el rendimiento.

Historia y evolución del estándar

HTML nació en el CERN a comienzos de los noventa para compartir documentos científicos entre computadoras distintas. Su historia está marcada por la “guerra de los navegadores”, la llegada de los estándares y, finalmente, un acuerdo para abandonar las versiones numeradas.

Hitos de HTML y CSS
Año Hito
1989–1991 Tim Berners-Lee propone el proyecto en el CERN y crea el primer navegador (WorldWideWeb), el primer servidor y las primeras páginas. HTML se inspira en SGML, un estándar para describir lenguajes de marcado.
1993 El navegador Mosaic populariza la web fuera del ámbito académico. Las etiquetas que entendían los navegadores se documentan sin un estándar formal.
1995 Se publica HTML 2.0 (RFC 1866), el primer estándar reconocido, con formularios, tablas y mapas de imagen.
1996 El W3C publica la primera recomendación de CSS, pensada para separar la presentación del contenido.
1997–1999 HTML 3.2, HTML 4.0 y HTML 4.01 incorporan hojas de estilo, scripts, marcos y mejoras de accesibilidad. Es la época en que las tablas se usaban para maquetar.
2000 XHTML 1.0 reformula HTML como una aplicación de XML, con reglas más estrictas. Su adopción masiva fracasa por la rigidez y los problemas de compatibilidad.
2004 Apple, Mozilla y Opera crean el WHATWG para continuar el desarrollo de HTML de forma abierta, en respuesta al abandono de XHTML 2.0.
2008–2014 Se publica el primer borrador de HTML5 y, en 2014, la recomendación del W3C. Incorpora etiquetas semánticas, audio, video, canvas, formularios mejorados y APIs.
2019–hoy El W3C y el WHATWG acuerdan continuar con un único HTML Living Standard: el estándar se actualiza de forma continua y los navegadores lo implementan sin esperar “versiones”.
“HTML5” no es una versión cerrada

Cuando decimos HTML5 solemos referirnos a un conjunto de tecnologías (HTML, CSS3 y APIs del navegador). Desde 2019 el estándar es un documento vivo: no existe un HTML6, sino cambios permanentes en el Living Standard.

La guerra de los navegadores

Durante los noventa, Netscape e Internet Explorer agregaban etiquetas propias para diferenciarse. El resultado fueron páginas que solo funcionaban en un navegador y un enorme costo de mantenimiento. La creación del W3C y, más tarde, del WHATWG, buscó que todos implementaran el mismo estándar. Esa es la razón por la que hoy escribimos HTML estándar y verificamos la compatibilidad antes de usar una función nueva.

Fundamentos de HTML

Todo documento HTML se construye con elementos. Un elemento está formado por una etiqueta de apertura, contenido y una etiqueta de cierre. Las etiquetas se escriben entre signos de menor y mayor.

Etiqueta de apertura
<p class="destacado">: indica qué elemento empieza.
Atributo
class="destacado": información extra, siempre como nombre="valor".
Contenido
Hola, mundo. y el elemento anidado <strong>.
Etiqueta de cierre
</p>: indica dónde termina el elemento.

Reglas de escritura

  • Las etiquetas se anidan correctamente: el último elemento abierto es el primero en cerrarse.
  • Algunos elementos no tienen contenido ni cierre, como <img>, <br>, <hr>, <input>, <meta> o <link>. Se los llama elementos vacíos.
  • Los nombres de etiquetas y atributos no distinguen mayúsculas de minúsculas, pero la convención —y el estilo del estándar— es escribirlos en minúsculas.
  • Los valores de los atributos van entre comillas dobles. Las comillas simples son válidas, pero conviene ser consistente.
  • El contenido se escribe una sola vez: los espacios y saltos de línea repetidos se colapsan al mostrarse.
HTML no es XHTML

En HTML5 no hace falta cerrar los elementos vacíos con una barra: <br> es correcto y <br /> también se acepta, pero la barra no tiene efecto. Tampoco se usan espacios antes del >.

Fundamentos de CSS

CSS (Cascading Style Sheets, hojas de estilo en cascada) es el lenguaje que describe la presentación de un documento. Se creó en 1996 para resolver un problema concreto: el HTML estaba lleno de etiquetas y atributos de estilo (<font>, bgcolor, align) que mezclaban contenido y apariencia.

Una regla CSS tiene tres partes:

  • Selector: p, indica a qué elementos se aplica.
  • Declaración: color: #292524;, formada por propiedad y valor.
  • Bloque: las declaraciones van entre llaves y separadas por punto y coma.

La palabra cascada hace referencia al conjunto de reglas que decide qué estilo gana cuando dos reglas afectan al mismo elemento. Lo veremos en detalle en la clase 9.

Errores comunes

Revisá estos puntos
  • Olvidar el <!DOCTYPE html>: el navegador entra en un modo de compatibilidad con páginas antiguas.
  • No declarar <meta charset="utf-8">: las tildes y la ñ se ven mal.
  • Omitir el <title>: la pestaña y los resultados de búsqueda quedan sin nombre.
  • Cerrar mal las etiquetas: <p><strong>texto</p></strong>.
  • Usar etiquetas de presentación obsoletas como <font>, <center> o el atributo bgcolor.
  • Pensar que HTML “da estilos”: para eso está CSS.

Actividad práctica

Crear la primera página del portafolio del curso y comprobar que el navegador la interpreta como HTML5.

  1. Crear una carpeta llamada clase-01 y dentro un archivo index.html.
  2. Escribir la estructura mínima: DOCTYPE, html con lang="es", head y body.
  3. En el head, agregar charset, viewport y un title descriptivo.
  4. En el body, incluir un h1 con el nombre, un párrafo de presentación y una lista con tres intereses.
  5. Agregar un enlace a una página externa que visites seguido.
  6. Agregar una hoja de estilos embebida con <style> que cambie la tipografía y el color del texto.
  7. Abrir el archivo en el navegador y luego inspeccionarlo con F12: identificar html, head y body en el panel Elements.

Para entregar: el archivo index.html y una captura del panel de elementos mostrando la estructura del documento.

Resumen

  • HTML es un lenguaje de marcado declarativo: describe estructura y significado, no comportamiento.
  • Nació en el CERN a comienzos de los noventa y se estandarizó en el W3C y luego en el WHATWG.
  • Desde 2019 es un estándar vivo, sin versiones numeradas.
  • Un elemento combina etiquetas, atributos y contenido; algunos elementos son vacíos.
  • CSS se ocupa de la presentación y se conecta con HTML mediante selectores.
  • Separar estructura, presentación y comportamiento es la base de un sitio mantenible.
