Clase 02

Estructura de un documento HTML

Un documento HTML no es una lista suelta de etiquetas: es un árbol con una raíz, un encabezado con metadatos y un cuerpo con el contenido visible. En esta clase vemos cómo se organiza y cómo lo interpreta el navegador.

Objetivos
  • Entender qué es el DOM y cómo se relaciona con el código HTML.
  • Identificar los componentes obligatorios de un documento.
  • Organizar correctamente el head y el body.
  • Reconocer errores de estructura en documentos propios y ajenos.

El modelo de objetos del documento (DOM)

El DOM (Document Object Model) es la representación en memoria que el navegador construye a partir del HTML. Es un árbol de nodos: cada elemento, cada texto y cada comentario es un nodo, y todos descienden de un nodo raíz llamado document.

Cuando el navegador recibe un archivo HTML, lo parsea (analiza), corrige lo que puede, construye el árbol y recién entonces lo pinta en pantalla. Por eso el HTML que escribimos y el DOM que existe en memoria pueden no ser idénticos: el navegador normaliza el marcado y completa estructuras faltantes.

Tipos de nodos

Nodo documento
La raíz, document. Desde ahí se accede a todo el árbol.
Nodos de elemento
Cada etiqueta: html, body, h1, p, etc.
Nodos de texto
El contenido escrito entre etiquetas, incluidos los espacios.
Nodos de comentario
Los comentarios <!-- ... -->, que existen en el árbol pero no se muestran.
HTML no es el DOM

El archivo HTML es el texto que escribimos; el DOM es el objeto vivo que el navegador crea a partir de ese texto. JavaScript puede agregar, quitar o modificar nodos, y el DOM cambia sin que el archivo original se modifique. Por eso “ver código fuente” y “ver en el inspector” no siempre muestran lo mismo.

Componentes de un documento web

Todo documento HTML5 tiene tres componentes básicos: la declaración de tipo, el elemento raíz y la división entre encabezado y cuerpo.

Componentes principales de un documento HTML5
Componente Función ¿Obligatorio?
<!DOCTYPE html> Indica que el documento es HTML5 y activa el modo estándar del navegador. Sí
<html lang="es"> Elemento raíz. El atributo lang declara el idioma del contenido. Sí
<head> Metadatos: título, codificación, estilos, scripts, descripción. Sí
<body> Contenido visible del documento. Sí

El DOCTYPE no es una etiqueta HTML: es una instrucción especial que debe ir en la primera línea. En HTML5 es simplemente <!DOCTYPE html>; en versiones anteriores incluía una referencia larga al DTD.

La estructura del encabezado (<head>)

El head no se ve, pero define cómo se comporta y se presenta el documento. Estos son los elementos que conviene incluir siempre, en este orden:

Elementos habituales del encabezado
Elemento Para qué sirve
<meta charset="utf-8"> Declara la codificación. Debe aparecer en los primeros 1024 bytes del archivo.
<meta name="viewport" …> Le indica al navegador móvil que use el ancho del dispositivo.
<title> Nombre de la pestaña y título en resultados de búsqueda. Es obligatorio y debe ser único por página.
<meta name="description"> Resumen para buscadores y vistas previas. No mejora el posicionamiento por sí solo, pero ayuda a mostrar un buen fragmento.
<link rel="stylesheet"> Vincula la hoja de estilos externa.
<link rel="icon"> Define el favicon.
<style> Estilos embebidos. Útil para ejemplos o páginas de un solo archivo.
<script defer src="…"> Carga JavaScript sin bloquear el análisis del documento.
El título no es el h1

El title aparece en la pestaña y en los resultados de búsqueda; el h1 es el título visible dentro de la página. Suelen coincidir en significado, pero no son lo mismo y no deben faltar.

La estructura del cuerpo (<body>)

El body contiene todo lo visible. Para que la página sea comprensible por personas y por tecnologías de asistencia, conviene organizarlo con regiones semánticas:

  • <header>: encabezado de la página o de una sección.
  • <nav>: conjunto de enlaces de navegación.
  • <main>: contenido principal, uno solo por página.
  • <aside>: contenido complementario.
  • <footer>: pie de página o de sección.
  • <section> y <article>: bloques temáticos y piezas autónomas de contenido.

Estas etiquetas no cambian la apariencia por sí solas, pero sí la forma en que el navegador, los lectores de pantalla y los buscadores entienden la página. Son la base de la accesibilidad.

Errores comunes

Revisá estos puntos
  • Escribir contenido visible dentro del head: el navegador lo mueve al body y la estructura queda impredecible.
  • Usar más de un main por página.
  • Omitir el lang del elemento html: los lectores de pantalla no saben en qué idioma leer.
  • Repetir el mismo title en todas las páginas del sitio.
  • Colocar la hoja de estilos al final del body: la página se muestra sin estilos hasta que termina de cargar.
  • Anidar un header o un footer dentro de otro sin que representen regiones distintas.

Actividad práctica

Comparar el código fuente de un sitio real con el árbol que construye el navegador.

  1. Elegir un sitio de noticias o el sitio de la universidad y abrirlo en el navegador.
  2. Ver el código fuente con Ctrl + U e identificar DOCTYPE, html, head y body.
  3. Anotar cinco elementos que estén dentro del head y explicar para qué sirve cada uno.
  4. Abrir las herramientas de desarrollo con F12, ir a Elements y desplegar el árbol hasta encontrar el contenido principal.
  5. Modificar un texto desde el inspector, sin guardar, y recargar la página para comprobar que el cambio se pierde.
  6. Crear un documento propio con la estructura completa, al menos tres regiones semánticas y un título coherente.

Para entregar: el documento propio y una breve comparación entre el código fuente y el DOM observado en el inspector.

Resumen

  • El DOM es el árbol de nodos que el navegador construye a partir del HTML.
  • Todo documento HTML5 lleva DOCTYPE, html con lang, head y body.
  • El head contiene metadatos: codificación, viewport, título, descripción, estilos y scripts.
  • El body contiene el contenido visible y se organiza con regiones semánticas.
  • Un solo main por página y un title único son reglas básicas de calidad.
