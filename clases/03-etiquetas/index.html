Clase 03

Etiquetas principales y secundarias

HTML ofrece más de cien elementos. Conocer para qué sirve cada uno evita dos extremos: usar siempre div o elegir etiquetas por su apariencia en lugar de por su significado.

Objetivos
  • Distinguir elemento, etiqueta, atributo y contenido.
  • Clasificar las etiquetas según su función y su comportamiento.
  • Reconocer las etiquetas principales y las secundarias.
  • Elegir alternativas actuales a las etiquetas obsoletas.

Elemento, etiqueta y atributo

Estas tres palabras se usan a veces como sinónimos, pero no lo son. La etiqueta es la marca escrita; el elemento es la pieza completa (apertura, contenido y cierre); el atributo agrega información al elemento.

  • img es la etiqueta y el tipo de elemento.
  • src, alt y width son atributos.
  • "plano.svg" y "Plano del aula" son los valores de esos atributos.
  • El elemento no tiene contenido ni cierre: es un elemento vacío.

Atributos globales y específicos

Los atributos globales se pueden usar en cualquier elemento: id, class, lang, title, hidden, tabindex, data-*, aria-* y role. Los específicos solo tienen sentido en ciertos elementos: href en a, alt en img, for en label, colspan en td.

Un identificador por documento

El valor de id debe ser único en toda la página. Se usa para anclas, para asociar etiquetas de formulario y para seleccionar con CSS o JavaScript. Para agrupar varios elementos, se usa class.

Clasificación de las etiquetas

No existe una única clasificación oficial. La más útil para aprender es combinar tres criterios: la función, el comportamiento en el flujo del texto y la frecuencia de uso.

Según su función

Familias de elementos según su función
Familia Ejemplos Para qué
Documento html, head, body Estructura general del archivo.
Semántica estructural header, nav, main, section, article, aside, footer Regiones y bloques de contenido.
Texto h1–h6, p, strong, em, blockquote, code Organizar y dar significado al texto.
Listas ul, ol, li, dl, dt, dd Enumeraciones y glosarios.
Enlaces y medios a, img, picture, audio, video, iframe Navegación y contenido incrustado.
Tablas table, caption, thead, tr, th, td Datos tabulares.
Formularios form, label, input, select, textarea, button Recolectar datos del usuario.
Interacción details, summary, dialog Comportamientos nativos sin JavaScript.

Según su comportamiento en el flujo

Elementos de bloque y elementos de línea
Comportamiento Ejemplos Cómo se ubican
Bloque h1, p, div, section, ul, table, form Empiezan en una línea nueva y ocupan todo el ancho disponible.
Línea a, span, strong, em, code, label Siguen el flujo del texto; no fuerzan un salto de línea.
Reemplazados img, video, iframe, input Se comportan en línea, pero tienen dimensiones propias y contenido externo.

Este comportamiento se puede cambiar con CSS mediante la propiedad display. La etiqueta describe el significado; el CSS decide cómo se muestra.

Principales y secundarias

La distinción entre principales y secundarias es didáctica, no oficial. Las principales son las que aparecen en casi cualquier página y permiten armar la estructura completa. Las secundarias son especializadas: aportan significado en contextos concretos y muchas veces pasan desapercibidas.

div y span no son la opción por defecto

Son contenedores sin significado. Se usan cuando ningún elemento semántico describe el contenido, por ejemplo para agrupar elementos con fines de diseño. Si el contenido es un párrafo, un título, una lista o una navegación, corresponde la etiqueta semántica.

Etiquetas secundarias

Las etiquetas secundarias agregan matices de significado. Estas son las más útiles:

b, i y u siguen siendo válidas

No están obsoletas, pero no aportan significado semántico. Si querés indicar importancia, usá strong; si querés indicar énfasis, usá em. El subrayado (u) se confunde con un enlace: reservalo para errores ortográficos o nombres propios en chino, y para el resto usá CSS.

Compatibilidad y renderizado

Todos los navegadores actuales implementan el mismo estándar, pero no al mismo ritmo. Una función reciente puede no existir en un navegador viejo o comportarse distinto. La estrategia es escribir HTML válido, verificar el soporte y prever una alternativa.

  • Consultar Can I use antes de adoptar una etiqueta o propiedad nueva.
  • Revisar la tabla de compatibilidad de MDN, que indica desde qué versión está disponible cada función.
  • Probar en al menos dos motores distintos (por ejemplo, Chromium y Firefox) y en un dispositivo móvil real o emulado.
  • Aplicar mejora progresiva: el contenido y las funciones básicas deben funcionar sin lo último; las mejoras se agregan si el navegador las soporta.
  • Validar el HTML: los navegadores toleran errores, pero cada uno los corrige a su manera.

Etiquetas desconocidas

Si el navegador encuentra una etiqueta que no conoce, no rompe la página: la trata como un elemento genérico en línea. Eso no significa que sea una buena idea inventar etiquetas: los elementos personalizados válidos llevan un guion (mi-componente) y necesitan JavaScript para definirse. Para dar estilo, usá clases sobre elementos existentes.

Actividad práctica

Refactorizar una noticia

Partí de este marcado y reescribilo con etiquetas semánticas:

  1. Convertir el contenedor en un article y el título en un h2.
  2. Usar p para el texto y time con datetime para la fecha.
  3. Agregar un footer dentro del artículo con la fuente.
  4. Marcar una palabra clave con strong y una fecha límite con mark.
  5. Verificar el documento con el validador del W3C.
  6. Inspeccionar el resultado en Elements y comprobar que la estructura coincide con el significado.

Para entregar: el HTML refactorizado y una lista de las etiquetas usadas con una frase que explique por qué cada una es la adecuada.

Resumen

  • Un elemento combina etiqueta, atributos y contenido; los vacíos no tienen cierre.
  • Los atributos globales sirven en cualquier elemento; los específicos, solo en algunos.
  • Las etiquetas se clasifican por función, por comportamiento en el flujo y por frecuencia de uso.
  • Las principales estructuran el documento; las secundarias aportan matices de significado.
  • div y span son contenedores sin semántica: no son la opción por defecto.
  • Las etiquetas obsoletas se reemplazan por CSS o por elementos semánticos actuales.
