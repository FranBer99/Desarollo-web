Clase 04

Control de texto

El texto es el contenido más importante de la web. Esta clase trata cómo insertarlo, cómo jerarquizarlo, cómo darle significado y cómo definir su apariencia con CSS sin volver a mezclar estructura y presentación.

Objetivos
  • Insertar texto y caracteres especiales de forma correcta.
  • Organizar el contenido con encabezados, párrafos y listas.
  • Elegir etiquetas semánticas de formato en lugar de etiquetas visuales.
  • Aplicar estilos tipográficos legibles y responsivos con CSS.

Insertar texto

El texto se escribe directamente dentro del body, agrupado en párrafos con <p>. El navegador colapsa los espacios en blanco: varios espacios, tabulaciones y saltos de línea se muestran como un solo espacio. Para conservar el formato original se usa <pre> o la propiedad CSS white-space.

Caracteres especiales y entidades

Algunos caracteres tienen significado en HTML y no se pueden escribir directamente: si escribís < el navegador cree que empieza una etiqueta. Para mostrarlos se usan entidades, que comienzan con & y terminan con ;.

Entidades HTML de uso frecuente
Se escribe Se ve Cuándo usarla
&lt;<Mostrar el signo menor.
&gt;>Mostrar el signo mayor.
&amp;&Mostrar el ampersand.
&quot;"Comillas dentro de atributos.
&nbsp; Espacio que no se corta entre dos palabras.
&copy;©Símbolo de copyright.
&mdash;—Raya o guion largo.
&hellip;…Puntos suspensivos.

También existen referencias numéricas: &#169; produce © y &#xA9; produce el mismo carácter en hexadecimal.

Codificación

El texto se guarda como bytes. La codificación indica qué carácter corresponde a cada byte. Si el archivo está guardado en UTF-8 pero el navegador lo interpreta como ISO-8859-1, las tildes y la ñ se ven como símbolos raros. Declarar <meta charset="utf-8"> y guardar el archivo en UTF-8 evita el problema.

Saltos de línea y separadores

<br> inserta un salto de línea dentro del mismo bloque. Se usa en poemas, direcciones y letras de canciones, no para separar párrafos: para eso se usa un nuevo <p> o márgenes CSS. <hr> representa un cambio temático entre secciones; no es una línea decorativa.

Jerarquizar el contenido

Los encabezados <h1> a <h6> expresan la estructura del documento, como los títulos y subtítulos de un libro. No son tamaños de letra: el tamaño se cambia con CSS. Un lector de pantalla, un buscador o una herramienta de resumen usan esa jerarquía para navegar.

  • Un solo h1 por página, que describa el contenido principal.
  • No saltear niveles: un h3 va después de un h2, no directamente después del h1.
  • No elegir el nivel por el tamaño que se ve: elegilo por la relación con el contenido.
  • No usar encabezados vacíos ni encabezados solo para aplicar negrita.
  • Cada section conviene que tenga su propio encabezado.
Un encabezado, un tema

Si un texto no necesita un título en el índice del documento, probablemente no sea un encabezado. Para destacar una frase se usa strong o CSS, no un h4.

Formato y estilos de texto

HTML tiene dos grupos de etiquetas para el texto: las que aportan significado y las que solo cambian la apariencia. Las primeras son preferibles porque siguen siendo útiles cuando el CSS no carga, en lectores de pantalla y en buscadores.

Formato semántico frente a formato visual
Semántica Visual Diferencia
strong b strong indica importancia; b solo llama la atención.
em i em indica énfasis; i indica otra voz o idioma.
del s del marca contenido eliminado; s, contenido obsoleto.
code tt (obsoleta) code identifica código; tt era solo tipografía.

Énfasis e importancia

strong se usa para advertencias, datos críticos y palabras clave; em, para cambiar la entonación de una frase. Se pueden anidar: <strong><em>muy importante</em></strong>.

Citas

<q> es una cita corta en línea y el navegador agrega las comillas. <blockquote> es una cita en bloque. El atributo cite acepta la URL de la fuente, no el nombre del autor.

Texto preformateado y código

<pre> conserva espacios y saltos de línea; <code> marca un fragmento de código. Se combinan para mostrar bloques de código, como en este sitio. Para la entrada del usuario se usa kbd; para la salida de un programa, samp; para variables, var.

Fechas, abreviaturas y datos de contacto

  • <time datetime="2026-10-28">: fecha legible por máquinas.
  • <abbr title="HyperText Markup Language">HTML</abbr>: sigla con su significado.
  • <address>: datos de contacto del autor o de la sección, no una dirección postal cualquiera.
  • <cite>: título de una obra, no el nombre de la persona que la escribió.

Listas

Las listas organizan elementos relacionados. HTML ofrece tres tipos:

  • No ordenadas (ul): el orden no importa.
  • Ordenadas (ol): el orden importa; se numeran solas.
  • De descripción (dl): pares de término y definición.

ol acepta start (número inicial), reversed (orden inverso) y type (1, a, A, i, I). Cada li puede llevar value para forzar su número.

Las listas de navegación también son listas: un nav con un ul y varios li es más accesible que una serie de enlaces sueltos. Con CSS se pueden mostrar en horizontal y sin viñetas.

Comentarios

Los comentarios se escriben entre <!-- y -->. No se muestran en la página, pero sí viajan en el archivo y son visibles en el código fuente.

Los comentarios no son privados

Cualquiera puede verlos con “ver código fuente”. Nunca escribas contraseñas, claves de API, datos personales ni instrucciones internas en un comentario. Tampoco uses comentarios para “desactivar” código que ya no se usa: conviene eliminarlo y dejarlo en el control de versiones.

Un comentario útil explica por qué se tomó una decisión o delimita una sección larga. Un comentario que repite lo que la etiqueta ya dice (<!-- párrafo --> antes de un p) agrega ruido.

La apariencia del texto se define con CSS. Estas son las propiedades fundamentales:

Legibilidad

  • El ancho de lectura ideal ronda los 45 a 75 caracteres; en CSS se limita con max-width: 65ch.
  • La altura de línea cómoda para texto corrido está entre 1.5 y 1.8.
  • El texto alineado a la izquierda es más fácil de leer que el justificado, que genera ríos de espacio.
  • El contraste mínimo recomendado es 4.5:1 para texto normal y 3:1 para texto grande.
  • No uses mayúsculas sostenidas para párrafos largos.
  • Respetá el zoom del navegador: usá unidades relativas (rem, em) y evitá bloquear el escalado.
El texto no se convierte en imagen

Nunca uses una imagen para mostrar texto: no se puede seleccionar, no se traduce, no se lee con lectores de pantalla y no se adapta al tamaño de la pantalla. HTML y CSS cubren todas las necesidades tipográficas.

Actividad práctica

Escribir una nota periodística sobre la historia de la web y aplicar todo lo visto sobre texto.

  1. Crear un documento con un h1 y una bajada de dos líneas.
  2. Organizar el cuerpo en tres secciones con h2; si hace falta, agregar un h3 dentro de alguna.
  3. Incluir al menos una cita en bloque con su fuente y una cita corta.
  4. Usar una lista ordenada para una cronología y una lista no ordenada para los protagonistas.
  5. Marcar una fecha con time, una sigla con abbr y una palabra clave con strong.
  6. Agregar un bloque de código o una muestra de texto preformateado.
  7. Definir en CSS la tipografía, el ancho de lectura, la altura de línea y el color; comprobar el contraste.
  8. Validar el HTML y revisar la página al 200 % de zoom.

Para entregar: el HTML, el CSS y una captura de la página con la jerarquía de encabezados visible en el panel Elements.

Resumen

  • El navegador colapsa los espacios; pre conserva el formato original.
  • Las entidades permiten mostrar caracteres reservados como &lt; y &amp;.
  • Los encabezados expresan jerarquía, no tamaño; un solo h1 por página.
  • Preferí etiquetas semánticas (strong, em, cite) antes que visuales (b, i).
  • Las listas se usan para contenido enumerado y también para menús de navegación.
  • Los comentarios son públicos: nunca incluyas información sensible.
  • La legibilidad se define con ancho de lectura, altura de línea, contraste y unidades relativas.
