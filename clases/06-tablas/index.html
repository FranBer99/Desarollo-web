Clase 06

Tablas

Las tablas nacieron para mostrar datos y durante años se usaron para maquetar páginas. Hoy volvieron a su función original: organizar información tabular de forma comprensible para todas las personas.

Objetivos
  • Entender por qué las tablas dejaron de usarse para maquetar.
  • Construir tablas con encabezados, cuerpo y pie.
  • Resolver tablas complejas con celdas combinadas y encabezados asociados.
  • Aplicar estilos responsivos sin romper la semántica.

Origen y uso actual

Las tablas se incorporaron a HTML a mediados de los noventa para presentar datos científicos y financieros. Como permitían alinear contenido en filas y columnas, los diseñadores las adoptaron para maquetar páginas completas: el encabezado en una fila, el menú en una celda, el contenido en otra y hasta imágenes transparentes de un píxel (spacer GIF) para forzar espacios.

Ese uso produjo páginas difíciles de mantener, lentas y casi imposibles de leer con un lector de pantalla, porque el orden de lectura seguía la estructura de la tabla y no el contenido. Con la llegada de CSS, el maquetado se trasladó a hojas de estilo y las tablas recuperaron su propósito: datos que se relacionan en filas y columnas.

¿Tabla o diseño con CSS?
Situación Herramienta
Notas por alumno, precios, horarios, comparativas Tabla HTML.
Distribuir el encabezado, el menú y el contenido CSS Grid o Flexbox.
Alinear un formulario o una tarjeta CSS.
Datos que deben leerse en filas y columnas Tabla HTML con encabezados y leyenda.
No vuelvas al maquetado con tablas

Usar tablas para distribuir una página obliga a simular el diseño con celdas, complica el responsive y confunde a las tecnologías de asistencia. Si encontrás una tabla de layout en un sitio antiguo, la alternativa es reescribir la estructura con HTML semántico y CSS.

Estructura básica

Una tabla se construye de afuera hacia adentro: el elemento table contiene una leyenda opcional, grupos de columnas y tres secciones (encabezado, cuerpo y pie). Cada fila es un tr y cada celda un th (encabezado) o un td (dato).

Elementos de una tabla
Elemento Función
tableContenedor de la tabla.
captionTítulo o descripción. Debe ser el primer hijo de table.
colgroup y colAgrupan columnas para aplicarles estilos.
theadFila o filas de encabezado.
tbodyCuerpo con los datos.
tfootPie: totales, promedios, notas.
trFila.
thCelda de encabezado; lleva scope.
tdCelda de dato.

El elemento caption no es decorativo: describe la tabla y se anuncia antes de recorrerla. Debe ir inmediatamente después de <table>, antes de thead.

scope indica si un th encabeza una columna (col), una fila (row), un grupo de columnas (colgroup) o un grupo de filas (rowgroup). Es la forma más simple y robusta de asociar encabezados con datos.

Tablas complejas

Cuando una celda ocupa más de una columna o más de una fila se usan colspan y rowspan. La tabla sigue siendo válida, pero el orden de lectura se vuelve más difícil: conviene reservar las celdas combinadas para casos realmente necesarios.

Encabezados asociados con headers

En tablas con varios niveles de encabezado, scope puede no alcanzar. En ese caso, cada celda de dato puede indicar los id de sus encabezados en el atributo headers, separados por espacios. Es más verboso, pero permite una lectura exacta.

Una tabla, un tema

No anides tablas para “ordenar” el contenido ni uses una tabla para comparar dos bloques de texto libre. Si la información no se lee naturalmente en filas y columnas, no es una tabla.

Accesibilidad

  • Leyenda: toda tabla de datos debería tener caption.
  • Encabezados: usá th con scope; no conviertas encabezados en td con negrita.
  • Orden de lectura: el HTML debe leerse de izquierda a derecha y de arriba abajo; las celdas combinadas no deberían romper esa lógica.
  • Celdas vacías: evitá dejarlas; si son necesarias, explicá el motivo en la leyenda.
  • Desplazamiento horizontal: si la tabla no entra en pantallas chicas, envolvela en un contenedor con overflow-x: auto, tabindex="0" y un role="region" con nombre accesible, para que se pueda recorrer con teclado.
  • Sin tablas de layout: la estructura de la página va con regiones semánticas y CSS.

Estilos

Los atributos de presentación de las tablas (border, cellpadding, cellspacing, width, align, bgcolor) están obsoletos. Todo se define con CSS:

  • border-collapse: collapse une los bordes de las celdas.
  • border-spacing solo tiene efecto con border-collapse: separate.
  • El rayado alternado (zebra) mejora la lectura de filas largas, pero no reemplaza a los encabezados.
  • Evitá table-layout: fixed si el contenido es variable y puede desbordar.
  • En pantallas chicas, priorizá el desplazamiento horizontal antes que reducir la letra.

Actividad práctica

Armar la tabla de horarios del cuatrimestre con datos reales o inventados.

  1. Crear una tabla con leyenda y columnas para los cinco días hábiles.
  2. Usar thead para los días, tbody para los horarios y tfoot para una nota general.
  3. Marcar los horarios como encabezados de fila con scope="row".
  4. Combinar al menos una celda con colspan y otra con rowspan.
  5. Aplicar estilos de borde, espaciado y rayado alternado solo con CSS.
  6. Envolver la tabla en un contenedor desplazable con nombre accesible y probarla a 320 px de ancho.
  7. Validar el HTML y revisar la tabla con el árbol de accesibilidad del navegador.

Para entregar: el HTML, el CSS y una captura del árbol de accesibilidad donde se vean la leyenda y los encabezados asociados.

Resumen

  • Las tablas son para datos tabulares; el layout se hace con CSS.
  • Una tabla completa lleva caption, thead, tbody y, si hace falta, tfoot.
  • th con scope asocia encabezados y datos.
  • colspan y rowspan combinan celdas; conviene usarlos con moderación.
  • Los atributos de presentación están obsoletos: los estilos van en CSS.
  • En pantallas chicas, la tabla se desplaza horizontalmente dentro de una región accesible.
