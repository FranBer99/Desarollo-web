Clase 08

Marcos

Los marcos dividían la ventana en documentos independientes. Fueron muy populares en los noventa, hoy están obsoletos, pero su sucesor —el iframe— sigue siendo útil para incrustar mapas, videos y aplicaciones de terceros.

Objetivos
  • Entender qué eran los marcos y por qué dejaron de usarse.
  • Distinguir frameset de iframe.
  • Incrustar contenido de forma responsiva y accesible.
  • Reconocer los riesgos de seguridad de incrustar sitios ajenos.

¿Qué son los marcos?

Un marco (frame) es una región de la ventana que muestra un documento HTML completo de forma independiente. La página que contiene los marcos no tiene contenido propio: solo define cómo se divide el espacio y qué documento se carga en cada parte.

La idea permitía mantener un menú fijo mientras cambiaba el contenido, algo que antes de CSS y de las aplicaciones de una sola página requería recargar toda la ventana. También permitía combinar contenido de distintos servidores en una misma pantalla. Los problemas superaron rápidamente a las ventajas.

frameset: el pasado

En HTML 4, una página con marcos reemplazaba el body por un frameset. El atributo rows o cols definía la división y cada frame apuntaba a un documento.

En HTML5 estos elementos están obsoletos: no forman parte del estándar y los validadores los rechazan. Algunos navegadores todavía los renderizan por compatibilidad, pero no se deben usar en un sitio nuevo.

Problemas de los marcos

  • Navegación rota: el botón “atrás” retrocede en un marco y no en la página completa.
  • URL única: no hay una dirección que represente el estado completo de la ventana; no se puede compartir ni guardar en favoritos.
  • Accesibilidad: los lectores de pantalla recorren documentos separados y el foco puede perderse entre marcos.
  • Adaptabilidad: los tamaños en porcentajes no se adaptan a pantallas pequeñas ni al zoom.
  • Impresión: imprimir varios documentos en una hoja es impredecible.
  • SEO: los buscadores indexan mal el contenido distribuido en marcos.
  • Mantenimiento: hay que coordinar varios archivos y nombres de destino.
La solución llegó con CSS

Un encabezado fijo, un menú lateral y un área de contenido se resuelven hoy con Grid o Flexbox, sin documentos separados y sin perder la URL única. Esa es la alternativa correcta a frameset.

iframe: el presente

iframe (inline frame, marco flotante) incrusta otro documento dentro de la página actual sin reemplazar el body. Es un elemento válido y ampliamente usado para mapas, videos, visores de documentos, widgets de pago y previsualizaciones.

Atributos de iframe
Atributo Para qué
srcURL del documento a incrustar.
titleNombre accesible del marco. Es obligatorio en la práctica: lo anuncia el lector de pantalla.
width y heightTamaño inicial. Mejor controlarlo con CSS.
loading="lazy"Retrasa la carga hasta que el marco se acerca al área visible.
sandboxRestringe lo que el documento incrustado puede hacer.
allowHabilita permisos concretos: cámara, micrófono, pantalla completa.
allowfullscreenPermite que el contenido pase a pantalla completa.
referrerpolicyControla qué información de origen se envía al sitio incrustado.
nameNombre del contexto de navegación, usado como destino de enlaces.
srcdocHTML embebido directamente en el atributo, sin archivo externo.

Uso responsable

  • Incrustá solo contenido en el que confiás: el iframe ejecuta código de otro origen.
  • Escribí siempre un title que describa el contenido, no “iframe”.
  • Aplicá el principio de mínimo privilegio en sandbox: empezar vacío y habilitar solo lo necesario.
  • Usá loading="lazy" para no cargar recursos pesados fuera de pantalla.
  • Definí dimensiones estables para evitar saltos de diseño; para videos, una relación de aspecto.
  • Ofrecé una alternativa: un enlace para abrir el contenido en una pestaña nueva.

Seguridad

Incrustar contenido ajeno es confiar parte de la página a un tercero. Los riesgos principales son:

  • Clickjacking. Un sitio malicioso incrusta tu página y superpone elementos invisibles para que el usuario haga clic en acciones que no quiere. Se mitiga con el encabezado X-Frame-Options: DENY o, mejor, con la directiva frame-ancestors de Content Security Policy.
  • Contenido no confiable. Un iframe sin sandbox puede ejecutar scripts, abrir ventanas, enviar formularios o acceder a datos del origen si comparte dominio.
  • Permisos excesivos. allow="camera; microphone" sin necesidad amplía la superficie de ataque.
  • Fuga de información. La URL de origen puede viajar en el encabezado Referer; referrerpolicy lo controla.
  • Contenido mixto. Un iframe http dentro de una página https se bloquea o genera advertencias.
sandbox no es decorativo

Sin tokens, el contenido incrustado no puede ejecutar scripts ni enviar formularios. Cada permiso que agregás (allow-scripts, allow-same-origin, allow-forms) amplía lo que puede hacer. Evitá combinar allow-scripts con allow-same-origin en contenido del mismo origen: el documento podría quitarse el sandbox a sí mismo.

Si el contenido es propio y de confianza, el iframe puede ser innecesario: conviene integrarlo con HTML normal. Si es de un tercero, verificá su política de privacidad, usá HTTPS y limitá los permisos.

Alternativas actuales

Qué usar en lugar de marcos
Necesidad Alternativa
Encabezado o menú fijo HTML semántico + CSS Grid/Flexbox + position: sticky.
Reutilizar un fragmento en varias páginas Inclusión en el servidor o un generador estático; en este sitio, el encabezado se repite porque no hay build.
Cargar contenido sin recargar fetch con JavaScript, o navegación normal si no es necesario.
Video <video> si el archivo es propio; iframe solo para plataformas externas.
Documento PDF Enlace de descarga o visor nativo; el iframe es una opción secundaria.
Mapa Iframe del proveedor con title, loading="lazy" y permisos mínimos.

Actividad práctica

Incrustar una página propia y comparar el resultado con un frameset obsoleto.

  1. Crear una página con un iframe que muestre el formulario de la clase 7.
  2. Agregar title, loading="lazy" y sandbox="allow-forms".
  3. Darle un tamaño estable con CSS y comprobar que se adapta a 320 px y a 1280 px.
  4. Agregar un enlace para abrir el formulario en una pestaña nueva, con rel="noopener".
  5. Navegar con Tab: comprobar que el foco entra al marco, recorre sus campos y sale.
  6. Escribir en un archivo aparte un frameset con dos marcos y validarlo: anotar los errores que devuelve el validador.
  7. Reemplazar ese frameset por una maqueta con Grid que muestre el mismo contenido en dos columnas.

Para entregar: la página con el iframe, el archivo del frameset con los errores del validador y la versión con Grid.

Resumen

  • Los marcos dividían la ventana en documentos independientes y hoy están obsoletos.
  • frameset rompe la URL única, la navegación, la accesibilidad y el responsive; CSS resolvió el problema.
  • iframe incrusta un documento dentro de otro y sigue siendo válido para contenido externo.
  • Todo iframe necesita title, dimensiones estables y, si es posible, loading="lazy".
  • sandbox y allow limitan lo que el contenido incrustado puede hacer.
  • Para contenido propio, HTML normal y CSS son casi siempre mejores que un iframe.
