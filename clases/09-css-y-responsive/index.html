Clase 09

Hojas de estilo y desarrollo responsivo

CSS decide cómo se ve el documento: tipografía, color, espacio, disposición y movimiento. Esta clase recorre sus reglas fundamentales y termina en el diseño de interfaces que funcionan en cualquier pantalla.

Objetivos
  • Incluir CSS en un documento y entender la cascada y la herencia.
  • Escribir selectores claros y de baja especificidad.
  • Dominar el modelo de caja, la tipografía, el color y los fondos.
  • Incorporar imágenes, audio, video, transformaciones y animaciones.
  • Construir interfaces responsivas, accesibles y mantenibles.

¿Qué es CSS?

CSS (Cascading Style Sheets) es el lenguaje que describe la presentación de un documento. Nació en 1996, cuando el HTML estaba lleno de etiquetas y atributos visuales, para separar el contenido de su apariencia. Hoy el estándar está dividido en módulos que evolucionan por separado (selectores, color, layout, animaciones), aunque coloquialmente se los siga llamando “CSS3”.

Formas de incluir CSS

  1. Hoja externa (recomendada): un archivo .css vinculado desde el head. Se cachea, se reutiliza en todas las páginas y mantiene el HTML limpio.
  2. Hoja interna: un bloque <style> en el head. Útil para ejemplos de un solo archivo o estilos críticos.
  3. Estilo en línea: el atributo style en un elemento. Tiene la especificidad más alta, no se reutiliza y mezcla contenido con presentación: se reserva para valores dinámicos.

@import permite cargar una hoja desde otra, pero bloquea la descarga y complica el rendimiento. Es preferible declarar varias hojas con <link>. El orden importa: las reglas posteriores pueden sobrescribir a las anteriores.

Sintaxis

  • Selector: a qué elementos se aplica.
  • Declaración: propiedad: valor;.
  • Bloque: declaraciones entre llaves.
  • Los comentarios se escriben entre /* y */.
  • Las propiedades se escriben en kebab-case: background-color.

Selectores

Un selector elige los elementos a los que se aplica una regla. Conocer los básicos evita depender de clases inventadas para todo.

Pseudoclases útiles

  • :hover, :focus, :focus-visible, :active.
  • :first-child, :last-child, :nth-child(2n), :nth-of-type(3).
  • :checked, :disabled, :required, :user-invalid.
  • :target: el elemento al que apunta el fragmento de la URL.
  • :has(): selecciona un padre según su contenido, por ejemplo article:has(img).
  • :where(): agrupa selectores sin sumar especificidad; :is() sí la suma.

Pseudoelementos

::before y ::after crean contenido decorativo antes o después de un elemento. Se usan con content y no deben contener información esencial: el texto generado por CSS puede no ser anunciado por los lectores de pantalla y no se puede seleccionar.

Clases antes que identificadores

Para dar estilo conviene usar clases reutilizables y dejar los id para anclas y asociaciones. Una clase bien nombrada (.tarjeta, .aviso--atencion) describe el componente; un #contenido suele ser único y difícil de reutilizar.

Cascada, especificidad y herencia

Cuando varias reglas afectan al mismo elemento, el navegador decide cuál gana. Esa decisión combina el origen de la regla, su importancia, su especificidad y el orden en que aparece.

Especificidad

Se calcula como una terna: identificadores, clases/atributos/pseudoclases y tipos/pseudoelementos. Cuanto más alta, más prioridad.

Peso de los selectores

style="..."Mayor que cualquier selector

Si dos reglas tienen la misma especificidad, gana la que aparece después en el archivo (o en la hoja que se carga después). El atributo !important invierte el orden normal y debe reservarse para excepciones justificadas, como utilidades de accesibilidad.

Herencia

Algunas propiedades se heredan de padres a hijos: color, font-family, font-size, line-height, text-align. Otras no: margin, padding, border, width, display. Las variables CSS también se heredan.

Los valores inherit, initial, unset y revert permiten forzar o revertir ese comportamiento. Las propiedades personalizadas (--color-acento) son la forma más práctica de compartir valores sin repetirlos.

La cascada no es el enemigo

Si necesitás usar !important o identificar selectores cada vez más largos, probablemente el problema sea la estructura del CSS, no la cascada. Mantené selectores simples, una sola capa de componentes y nombres claros.

Modelo de caja

Todo elemento visible es una caja rectangular compuesta por cuatro capas: contenido, relleno (padding), borde y margen. Entenderlas es imprescindible para calcular tamaños y espacios.

  • Con content-box (predeterminado), width mide solo el contenido: el total suma relleno y borde.
  • Con border-box, width incluye contenido, relleno y borde. Es lo que casi siempre se espera; se suele aplicar a todos los elementos con * { box-sizing: border-box; }.
  • Los márgenes verticales de cajas adyacentes pueden colapsar: el mayor gana, no se suman.
  • min-width, max-width, min-height y max-height limitan el crecimiento.
  • overflow decide qué pasa con el contenido que no entra: visible, hidden, auto, scroll.
  • outline no ocupa espacio y no afecta el modelo de caja; es ideal para el foco.

Display y posicionamiento

  • block, inline, inline-block, flex, grid, none.
  • position: static (predeterminado), relative, absolute, fixed, sticky.
  • z-index solo funciona en elementos posicionados o en contextos de apilamiento.
  • display: none quita el elemento del flujo y del árbol de accesibilidad; visibility: hidden lo oculta pero reserva el espacio.

Tipografía, color y fondos

Tipografía

Se define con font-family, que acepta una lista de fuentes de respaldo, y con font-size. Para textos largos conviene una altura de línea entre 1.5 y 1.8 y un ancho de 45 a 75 caracteres.

  • Peso: font-weight (400 normal, 600 seminegrita, 700 negrita).
  • Estilo: font-style: italic; no lo uses para simular énfasis semántico.
  • Alineación: text-align: left | center | right | justify.
  • Transformación: text-transform: uppercase | lowercase | capitalize.
  • Decoración: text-decoration: underline | line-through | none.
  • Sombra: text-shadow, con moderación.
  • Cortes: overflow-wrap: break-word y hyphens: auto.

Las fuentes web se cargan con @font-face o con un servicio externo. Cada archivo adicional es una descarga: limitá los pesos y usá font-display: swap para que el texto se vea mientras carga. Las pilas de fuentes del sistema son la opción más rápida y privada.

Color

Un color se puede escribir con nombre (rebeccapurple), hexadecimal (#4f46e5), rgb(), hsl() u oklch(). Los formatos modernos aceptan transparencia con una barra: rgb(79 70 229 / 0.5).

El contraste entre texto y fondo es un requisito de accesibilidad: 4.5:1 para texto normal y 3:1 para texto grande. El color por sí solo nunca debe ser la única forma de transmitir información (por ejemplo, un error).

Fondos y gradientes

background-color pinta un color; background-image acepta imágenes y gradientes. Los gradientes son imágenes generadas por CSS: no requieren archivos y se adaptan al tamaño del elemento.

Otras propiedades de fondo son background-repeat, background-position, background-size (con cover y contain), background-attachment y background-clip. Se pueden combinar varias capas separadas por comas.

Imágenes, audio y video

Imágenes

La etiqueta img es un elemento vacío y requiere src y alt. El texto alternativo describe la imagen para quien no puede verla; si es decorativa, se deja vacío (alt="") para que el lector de pantalla la ignore.

  • Declará width y height para reservar el espacio y evitar saltos de diseño.
  • max-width: 100% y height: auto hacen que la imagen sea fluida.
  • loading="lazy" posterga las imágenes fuera de pantalla.
  • object-fit: cover recorta sin deformar; contain muestra completa.
  • Usá srcset y sizes para ofrecer versiones adecuadas al ancho de pantalla.
  • picture permite elegir formato (AVIF, WebP) o recorte según el dispositivo.

Audio y video

HTML5 incorporó audio y video sin necesidad de plugins. El navegador elige la primera fuente compatible y muestra los controles nativos con controls.

  • Ofrecé al menos dos formatos: WebM y MP4 son la combinación habitual.
  • Los subtítulos con track son obligatorios para contenido con voz.
  • preload="metadata" evita descargar todo el archivo de entrada.
  • El poster muestra una imagen antes de reproducir.
  • No reproduzcas audio automáticamente: los navegadores lo bloquean y resulta invasivo.
  • Un video decorativo de fondo debe ir muted, loop y sin controles, con una alternativa estática.

Transformaciones y animaciones

transform mueve, escala, rota o inclina un elemento sin modificar el flujo del documento. transition interpola un cambio de estado y animation ejecuta una secuencia definida con @keyframes.

  • Animá transform y opacity: se resuelven en la GPU y no fuerzan recálculo de layout.
  • Evitá animar width, height, top o margin en bucles.
  • transition: all anima propiedades no deseadas; enumerá las que cambian.
  • No superes tres destellos por segundo: puede provocar convulsiones.
  • Ofrecé una forma de pausar animaciones largas y respetá prefers-reduced-motion.
  • La información nunca debe depender de una animación para entenderse.

Desarrollo responsivo

Una interfaz responsiva se adapta al tamaño de la pantalla, a la orientación, al zoom y al tipo de entrada. No se trata de hacer “una versión para celular”, sino de que el mismo contenido funcione en todos los contextos.

La metaetiqueta viewport

Sin esta etiqueta, los navegadores móviles simulan una pantalla de escritorio y reducen todo. Debe ir en el head:

No uses user-scalable=no ni maximum-scale=1: impiden hacer zoom y perjudican a quien necesita ampliar el texto.

Mobile first y media queries

Se escribe primero el diseño para pantallas angostas y luego se amplía con min-width. Los puntos de corte se eligen según el contenido, no según marcas de dispositivos.

Texto e imágenes fluidos

  • clamp() ajusta el tamaño de letra entre un mínimo y un máximo.
  • max-width: 65ch mantiene una línea de lectura cómoda.
  • img { max-width: 100%; height: auto; } evita desbordes.
  • aspect-ratio reserva la proporción de videos e imágenes.
  • Evitá anchos fijos en píxeles para bloques principales.

Container queries

Las consultas de contenedor permiten adaptar un componente al ancho de su contenedor, no al de la ventana. Son ideales para tarjetas que se usan en una barra lateral o en una grilla ancha.

Otros aspectos

  • Navegación: un menú horizontal puede envolverse o convertirse en una lista vertical sin JavaScript.
  • Tablas: se desplazan horizontalmente dentro de una región accesible (clase 6).
  • Áreas táctiles: al menos 24 × 24 px, y 44 × 44 px como objetivo cómodo.
  • Zoom: probá al 200 %; el contenido no debe perderse ni superponerse.
  • Orientación: verificá horizontal y vertical.
  • Impresión: una hoja @media print puede ocultar la navegación y mostrar las URLs.

Buenas prácticas

  • Organizá el CSS por capas: tokens, base, layout, componentes y utilidades.
  • Nombres por función: .tarjeta, .aviso, .pager; evitá .verde-grande.
  • Baja especificidad: clases simples; evitá #id y selectores larguísimos.
  • Sin estilos en línea salvo valores dinámicos calculados.
  • Variables para colores, tipografías, radios y espaciados.
  • Un solo sentido de espaciado: por ejemplo, márgenes solo hacia abajo o gap en contenedores flexibles.
  • Accesibilidad: contraste, foco visible, movimiento reducido, texto ampliable.
  • Rendimiento: menos fuentes y pesos, imágenes optimizadas, CSS crítico en páginas grandes.
  • Compatibilidad: verificá las funciones nuevas con @supports y ofrecé una alternativa.
  • Herramientas: stylelint para errores, Prettier para formato y DevTools para depurar.
  • Documentación: comentarios de sección y un README que explique la estructura.
Capas y funciones modernas

@layer permite ordenar la cascada por capas, @supports aplica estilos solo si el navegador entiende una propiedad y el anidamiento nativo de CSS evita repetir selectores. Son herramientas útiles, pero conviene incorporarlas cuando el equipo y el público objetivo las puedan aprovechar.

Actividad práctica

Diseñar una página personal responsiva que reúna todo lo visto en la materia.

  1. Definir en :root al menos seis variables: colores, tipografía, radio y espaciado.
  2. Construir una portada con nombre, presentación y una grilla de tres tarjetas.
  3. Aplicar una escala tipográfica fluida con clamp() y un ancho de lectura de 65 caracteres.
  4. Usar un gradiente como fondo de la portada y verificar el contraste del texto.
  5. Incluir una imagen responsiva con picture o srcset, con texto alternativo.
  6. Agregar una transición en los enlaces o botones y una animación de entrada para las tarjetas.
  7. Respetar prefers-reduced-motion.
  8. Adaptar la grilla a una, dos y tres columnas; probar a 320, 768 y 1280 px.
  9. Validar el HTML y el CSS, y revisar el contraste y el foco con teclado.

Para entregar: el HTML, el CSS y capturas en los tres anchos, junto con el resultado de la validación.

Resumen

  • CSS separa la presentación del contenido; la hoja externa es la forma recomendada.
  • La cascada combina origen, importancia, especificidad y orden; conviene mantener la especificidad baja.
  • El modelo de caja suma contenido, relleno, borde y margen; border-box simplifica los cálculos.
  • Tipografía, color y fondos se controlan con propiedades y variables; el contraste es obligatorio.
  • Las imágenes necesitan dimensiones, texto alternativo y versiones adecuadas; el video necesita subtítulos.
  • transform, transition y @keyframes agregan movimiento, siempre respetando las preferencias del usuario.
  • El diseño responsivo combina viewport, unidades relativas, Grid/Flexbox, media queries y container queries.
  • Un CSS mantenible usa nombres claros, capas, variables y verificación en navegadores reales.
